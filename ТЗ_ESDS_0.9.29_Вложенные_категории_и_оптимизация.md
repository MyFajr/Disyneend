# ESDS 0.9.29 — техническое задание: вложенные категории, полное управление файлами и оптимизация

База: ветка `fix/palette-library-management-0.9.28` (0.9.28). Результат — устанавливаемая сборка
плагина Obsidian (Android/Desktop), версия `0.9.29`. Палитра остаётся в режиме **Single Mode**;
разделение Light/Dark для палитр не возвращается.

## 1. Цели

1. **Категория в категории (вложенные категории).** Любую категорию палитр, фонов или стилей
   блоков можно переместить внутрь другой категории того же типа, вернуть в корень, создать
   подкатегорию прямо из меню категории.
2. **Полное управление файлами для категорий и элементов.** Создание, переименование, удаление,
   перемещение, сортировка (вручную, А—Я, Я—А, по количеству) — единообразно для всех трёх типов:
   палитры, фоны, стили блоков — и во всех местах: каталог библиотеки, секции «Общая палитра» и
   «Фон заметки», модальное окно «Категории…».
3. **Массовые операции.** Режим «Выделение»: выбрать все элементы коллекции или открытой
   категории, снять выбор, переместить, удалить, экспортировать ZIP/JSON. Дополнительно удаление
   категории **вместе со всеми вложенными элементами** (отдельный пункт меню с подтверждением).
4. **Исправить «плавающие» кнопки.** Внутри открытой категории кнопки карточек («Просмотр и
   применение», «Переименовать», «Переместить», «Удалить», «⋯») должны стоять строго внизу
   карточки ровными рядами, не перескакивать и не наезжать на превью независимо от длины названия.
5. **Оптимизация производительности.** Раскрытие/сворачивание секций, навигация по категориям и
   перерисовка превью не должны пересобирать весь модал целиком; на Android отклик мгновенный.
6. Доставка: ветка в GitHub + ZIP-архив ветки по прямой ссылке.

## 2. Модель данных (обратно совместимая)

- Категория: `{ id, name, order, protected, description?, parentId? }`.
- `parentId` — id родительской категории того же типа либо `''` (корень). Отсутствие поля
  читается как корень; старые библиотеки совместимы без миграции.
- Элементы (палитры/фоны/стили) продолжают ссылаться на категорию по имени; переименование
  категории обновляет имена у элементов, `parentId` детей не меняется.
- `ensureLibraryShape()` нормализует: `parentId` приводится к строке, несуществующие родители
  сбрасываются в корень, циклы разрываются в корень.

## 3. Правила вложенности

- Запрещено перемещать категорию в неё саму и в любого её потомка (защита от циклов).
- Глубина вложенности не ограничена, но меню перемещения показывает только корректные цели.
- При удалении категории:
  - «Удалить» (по умолчанию) — элементы переносятся в безопасную категорию (как в 0.9.28),
    дочерние категории поднимаются на уровень удаляемой;
  - «Удалить с элементами» — удаляются категория, все подкатегории и все их элементы
    (с подтверждением, в котором указано количество); избранное и активные выбора чистятся
    только по реально удалённым элементам соответствующего типа.
- Счётчик на плитке категории — количество элементов с учётом всех вложенных категорий.

## 4. Интерфейс каталога

- В корне показываются только корневые категории; внутри открытой категории — её подкатегории
  плитками, затем элементы.
- Кнопка «‹ Назад» ведёт к родительской категории (или в корень).
- Сортировка категорий: селект «Категории: вручную / А—Я / Я—А / по количеству» в каждом
  каталоге (состояние хранится на сессию модала для каждого типа).
- Меню категории «⋮» (палитры, фоны, стили): переименовать; ✚ новая подкатегория; ↳ переместить
  в категорию (поповер: «В корень», список допустимых категорий, «＋ Новая категория…»); ↑/↓;
  удалить; удалить с элементами. Системные (protected) категории можно перемещать и вкладывать,
  но нельзя переименовать и удалить.
- Модальное окно «Категории…» показывает дерево с отступами, теми же действиями и кнопками
  «＋ Новая категория» / «＋ Новая подкатегория».

## 5. Элементы внутри категории

Сохраняются и гарантируются все операции 0.9.28: просмотр/применение, переименование,
перемещение в категорию (пикер с учётом вложенности, отступы по уровню), дублирование,
экспорт, ↑/↓, удаление; массовый режим «Выбрать всё» / «Снять выбор» / «Переместить» /
«Удалить» / «ZIP» / «JSON». Совпадение имён разрешается автопридумыванием уникального имени
(политика 0.9.28, раздел 3).

## 6. Исправление раскладки карточек

- Карточка — вертикальный flex: заголовок (2 строки максимум, ellipsis), превью фиксированной
  высоты, блок кнопок прижат к низу карточки (`margin-top:auto`).
- Кнопки в блоке действий — одинаковая высота, перенос по сетке, обрезка длинных подписей;
  ряды кнопок во всех карточках одной строки сетки совпадают по вертикали.
- Убран конфликтующее глобальное правило `width:100%` для кнопок действий.
- Превью карточки получает `contain`, чтобы анимации/перерисовка не пересчитывали всю сетку.

## 7. Оптимизация производительности

- Раскрытие/сворачивание секций-аккордеонов больше не пересобирает весь модал: содержимое
  секции строится один раз по требованию и переиспользуется, переключение — локальное
  (класс + display + aria-expanded). Полный рендер происходит только при изменении данных.
- Навигация по каталогам (открытие категории, назад, сортировка, поиск) продолжает работать
  на локальном рендере без пересборки всего модала.
- Генерация пользовательского CSS остаётся пакетированной (debounce 32 мс) и не запускается
  повторно, если текст не изменился.
- Запрещено вводить новые полные `render()` на сценарии скролла/наведения; hover не является
  единственным способом доступа к функциям (Android).

## 8. Ограничения Android

- Никаких `window.prompt()`; текстовый ввод — модальными окнами; подтверждения — `confirm()`
  (сохраняется текущее поведение) или штатные модалы.
- Кнопки и пункты меню — сенсорные области ≥36px; длинные названия обрезаются, не ломая сетку.
- Поповеры меню располагаются внутри экрана.

## 9. Проверки перед выдачей

1. `node --check main.js`.
2. `manifest.json` и `versions.json` — валидный JSON, версия `0.9.29`.
3. Отсутствие `window.prompt(`.
4. Наличие в коде: `parentId`-нормализация, защита от циклов, «переместить в категорию»,
   «новая подкатегория», «удалить с элементами», сортировка категорий, локальное
   переключение секций (`_sectionBuilders`), прижатые кнопки карточек.
5. ZIP-архив ветки скачивается по прямой ссылке и содержит `main.js`, `manifest.json`,
   `styles.css`, `versions.json`.
