# Техническое задание — ESDS Palette & Category File Manager 0.9.24

## Цель
Полноценное управление категориями палитр как папками файлового менеджера непосредственно в каталоге ESDS, с приоритетом Obsidian Android.

## Модель данных
- Категория: стабильный id, уникальное имя, order, необязательный parentId.
- null/отсутствующий parentId означает корневой уровень; старые категории мигрируют без изменения.
- Палитры сохраняют прежний JSON-формат и поле category.
- Пустой сохранённый список категорий считается намеренно пустым и не восстанавливает категории по умолчанию.
- Удалённые встроенные палитры отмечаются в deletedBuiltinPaletteIds.

## Каталог и выделение
- Категории отображаются папками в основном каталоге.
- Выделение касанием прямо на карточке/чекбоксе категории.
- «Выбрать», «Выбрать всё» (текущий уровень), «Снять выделение», счётчик.
- Повторное касание в режиме выделения снимает выбор.
- Вложенные категории открываются как папки; «Назад» возвращает к родителю.
- Создание новой категории/подкатегории доступно прямо на текущем уровне каталога.
- Внутри категории доступен отдельный переход к палитрам этой категории.
- Сенсорные зоны и адаптивная компоновка для Android.

## Действия с категориями
- Массовое перемещение в корень или внутрь другой категории через сенсорный список назначения с отображением пути категории.
- Запрет циклов: нельзя переместить категорию внутрь себя или потомка.
- Массовое рекурсивное удаление выбранных категорий.
- Удаление родителя удаляет все вложенные категории и все палитры в них.
- Встроенные категории не защищены от удаления.
- Удаление встроенных палитр реализуется устойчивой записью tombstone; пользовательские палитры удаляются из userData.
- Подтверждение сообщает число удаляемых категорий и палитр.

## Действия с палитрами
- Сохраняются множественное выделение, выбор всех, снятие выбора, инверсия, сетка/список.
- Перемещение/копирование выбранных пользовательских палитр, переименование, удаление, ZIP-экспорт.
- Перемещение меняет только категорию, не трогая дизайн Light/Dark и JSON-поля.

## Надёжность и приёмка
- Стабильные ID и сохранение порядка.
- Снимок userData до массовых изменений и откат при ошибке сохранения.
- Статические проверки JS, JSON, CSS, ZIP и отсутствие data.json в установочном архиве.
- Ручной тест на реальном Obsidian Android обязателен отдельно и не подменяется статическими проверками.
