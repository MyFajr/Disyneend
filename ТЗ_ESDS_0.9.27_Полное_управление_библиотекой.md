# ТЗ ESDS 0.9.27 — Полноценное управление библиотекой (файлы, категории, массовые операции)

## 1. Общие сведения

- **Продукт:** плагин Obsidian «English Study Design Studio» (ESDS), id `english-study-design-studio`.
- **Базовая версия:** 0.9.26 (ветка `fix/palette-single-mode-0.9.26`).
- **Целевая версия:** 0.9.27.
- **Цель:** полноценная работа с библиотекой оформления (палитры, фоны, стили блоков) непосредственно внутри плагина: файловые операции (JSON/ZIP), управление категориями и элементами, массовые операции, сортировка. Плюс устранение обнаруженных неработоспособных участков кода и улучшение интерфейса.

## 2. Обнаруженные дефекты в 0.9.26 (обязательны к исправлению)

### D1. Критический: `window.prompt()` не работает в Obsidian (Electron)

Electron/Obsidian не поддерживает `window.prompt()` — вызов выбрасывает исключение
`prompt() is and will not be supported.`. В 0.9.26 от него зависят **7 действий**, и все они фактически нерабочие:

| № | Действие | Место в `main.js` |
|---|----------|-------------------|
| 1 | Переименование категории (менеджер категорий) | `CategoryManagerModal`, вызов `prompt('Новое название:' …)` |
| 2 | Создание категории (менеджер категорий) | `CategoryManagerModal`, вызов `prompt('Название категории:')` |
| 3 | Переименование палитры (каталог библиотеки) | `manageLibraryCatalogItem` |
| 4 | Перемещение элемента в категорию (каталог библиотеки) | `manageLibraryCatalogItem` |
| 5 | Переименование категории (меню папки палитр) | `openPaletteCategoryMenu` |
| 6 | Переименование палитры (меню карточки) | `openPaletteMenu` |
| 7 | Перемещение палитры в категорию (меню карточки) | `openPaletteMenu` |

**Требование:** заменить все `prompt()` на собственный модальный диалог ввода
(`TextPromptModal`): поле ввода, кнопки «Сохранить»/«Отмена», подтверждение по Enter,
запрет пустых значений. Перемещение в категорию — через модальный выбор категории
(существующая/новая), а не ручной ввод текста.

### D2. Меню управления категорией есть только у палитр

У папок фонов и стилей блоков в каталогах нет кнопки «⋯» с переименованием/удалением/
перестановкой категории. **Требование:** обобщить `openPaletteCategoryMenu` до
`openCategoryMenu(kind, …)` и подключить ко всем трём типам каталогов.

### D3. Нет массовых операций с элементами

Выбрать несколько палитр/фонов/стилей и выполнить общее действие невозможно
(частичная реализация только в диалоге ZIP-экспорта). **Требование:** режим
массового выделения в каталоге библиотеки (см. п. 3.4).

### D4. Неполная сортировка

- В каталоге библиотеки селектор сортировки только у палитр.
- Нет направлений «Я—А» и «Сначала старые», нет сортировки «по категориям».

### D5. Состояние каталога после переименования/удаления категории

`CategoryManagerModal` не обновляет активный выбор категории в студии
(`paletteCategory`, `libraryCategory`, `backgroundCategory`) — после переименования
открытая категория перестаёт совпадать и вьюха отображается некорректно.

## 3. Функциональные требования

### 3.1. Операции с палитрами (уже есть в 0.9.26 — сохранить и починить)

- Просмотр, применение, предпросмотр.
- Создание (конструктор), дублирование, редактирование цветов.
- **Переименование** (D1).
- **Перемещение в другую категорию** через модальный выбор (D1).
- Перестановка вверх/вниз внутри категории.
- **Удаление** с подтверждением; очистка избранного; сброс выбора при удалении активной палитры.
- Экспорт/импорт JSON (одиночный и множественный), ZIP-импорт, ZIP-экспорт.

### 3.2. Операции с фонами и стилями блоков

- **Удаление фонового оформления** (меню карточки и каталога) — есть, сохранить.
- Редактирование, дублирование, экспорт, перемещение в категорию, удаление.
- Управление категориями фонов и стилей (D2): создание, переименование, удаление
  с переносом элементов в резервную категорию, перестановка вверх/вниз.

### 3.3. Категории

- Создание (модальный ввод, проверка дубликатов, автогенерация уникального id).
- Переименование с каскадным обновлением элементов и активного выбора (D5).
- Удаление с подтверждением и переносом элементов в другую категорию.
- Перемещение категории по списку (вверх/вниз) — для всех трёх типов.
- Системные («защищённые») категории не удаляются и не переименовываются.

### 3.4. Массовые операции (новое)

В каталоге библиотеки («Личная коллекция оформления») — переключатель режима
выделения:

- Флажок на каждой карточке; «Выбрать всё», «Снять выбор», счётчик выбранных.
- **Переместить выбранные** в категорию (существующую или новую) — для всех типов.
- **Экспорт ZIP** выбранных палитр (формат `esds-palette-collection` с манифестом) —
  обобщается: ZIP строится для любого типа (фоны/стили — файлы JSON + манифест).
- **Экспорт JSON** выбранных элементов — единый файл
  `{ schemaVersion, type: 'esds-export', items: [...] }`.
- **Удалить выбранные** с подтверждением, очисткой избранного и корректным сбросом
  активного выбора.
- Выделение сбрасывается при смене типа каталога/категории/поиска.

### 3.5. Импорт/экспорт файлов

- Импорт JSON: одиночный элемент, несколько файлов, вся библиотека, ZIP-коллекция —
  сохранить; **добавить** импорт объединённого файла `esds-export` с маршрутизацией
  каждого элемента по его типу.
- Экспорт: одиночный JSON, текущий набор (theme pack), вся библиотека, ZIP.
- ZIP записывается в папку хранилища `ESDS Exports/`.

### 3.6. Сортировка

- Режимы: «По порядку добавления», «А—Я», «Я—А», «Сначала новые», «Сначала старые»,
  «По категориям» (категория → порядок → имя).
- Селектор сортировки во всех трёх каталогах: студийный раздел палитр, раздел фонов,
  раздел стилей, каталог библиотеки (для каждого типа).

## 4. Нефункциональные требования

- Совместимость с `data.json` 0.9.26 без миграций (обратная совместимость).
- Без новых зависимостей (ZIP пишется/читается встроенными средствами).
- Замена `confirm()` не требуется (работает в Electron), но сообщения формулируются
  явно и безопасно (отмена ничего не меняет; изменения применяются атомарно с
  откатом при ошибке сохранения).
- Код без комментариев-новодобавлений в стиле «шум»; единый стиль существующего кода.
- UI: русский язык, поддержка тёмной/светлой темы Obsidian, адаптивность,
  доступность (`aria-pressed`, `role`, фокус с клавиатуры).

## 5. Дизайн (UI)

- Панель массовых операций: липкая строка с действиями, счётчиком и кнопками
  «Выбрать всё/Снять», визуальное состояние выбранных карточек (рамка-акцент).
- Флажки выделения на карточках в режиме выделения.
- Модальный диалог ввода текста в общем стиле ESDS-кнопок и полей.
- Кнопка меню категории «⋯» на папках фонов и стилей блоков — как у палитр.

## 7. Критерии приёмки

1. Все действия из пп. 3.1–3.6 выполняются из UI без `prompt()`/консоли.
2. `node --check main.js` проходит; smoke-тест чистых функций библиотеки проходит.
3. Ни одна операция не повреждает `data.json`: при ошибке сохранения — откат.
4. Системные категории защищены; удаление категории переносит элементы, а не стирает их.
5. Массовое удаление/перемещение корректно чистит `favoriteItems` и активный выбор.
